* eimg — 截图与 OCR 一体化工具包

eimg 把「采集图像 → 识别文字 → 产出可用文本或链接」收成一个包。当前版本 *0.1.0* 交付
两组能力，都在本包内：截图链路（采集 / 选择预览 / 插入 / embark 集成，四个模块）与 OCR
链路（CLI + 纯逻辑 + 异步进程层 + 结果 buffer + transient 菜单）。

* 安装

** 前置

- *Emacs 29.1+* ： =Package-Requires= 的下限，代码用了 =keymap-set= 等 29.1 起的 API。
- *=python3=* ： =bin/eimg-ocr= 与 =bin/eimg-ocr-setup= 都是 Python 脚本，跑 CLI 必须有系统
  python3；elisp 侧不直接依赖 Python（只经 CLI 子进程间接使用）。
- 可选外部命令： =pdftoppm= 与 =pdfinfo= （poppler，PDF 栅格化 / 取总页数）、 =tesseract= 。
  缺 =pdftoppm= 时 PDF 输入无法识别；缺 =pdfinfo= 时页码越界可能静默截断
  （见「已知边界」）。
- 可选 *ollama* 后端：需要本地 ollama 服务 + 一个**显式配置**的视觉模型（本包不代跑
  ollama pull）。缺服务或缺模型即判该后端不可用， =auto= 会跳过它；可用性判据是 HTTP
  可达而非 =which ollama= ——典型形态是 ollama 装在 Windows 原生侧、WSL 里没有该命令，
  但经 mirrored 网络仍能连 =127.0.0.1:11434= 。

** 后端准备：四种方式与两条硬约束

两条硬约束（不变量，改动时不要打破）：

1. *首次安装必须显式运行* 。 =bin/eimg-ocr-setup= 只能由用户在终端里手动执行：Emacs 配置、
   =init= 与任何 hook 都不下载、不安装任何东西。菜单里的 =S= （ =eimg-ocr-setup-help= ）
   只是把指引写进 buffer，一条命令都不执行——后端与语言数据动辄数百 MB、数分钟，
   隐式触发会让「打开一个菜单」变成「机器上多了个虚拟环境」，失败时还找不到日志。
2. *=--dry-run= 可零副作用预览* 。它只打印将执行的命令与将下载的 URL、目标路径，
   零写入零联网；与 =--check= 叠加时等同 =--check= 。

| 命令                                     | 用途                                                       | 写入行为                                     |
|------------------------------------------+------------------------------------------------------------+----------------------------------------------|
| =bin/eimg-ocr-setup --check=             | 只读体检：后端可用性、配置文件与安装位置现状               | 不创建任何文件 / 目录                        |
| =bin/eimg-ocr-setup --reuse-pdf-toc-ocr= | 复用 pdf-toc-ocr 已装好 rapidocr 的 venv                   | 只写配置文件的 =python= 键（写前校验可执行） |
| =bin/eimg-ocr-setup --rapidocr=          | 新建 venv 并安装 rapidocr / onnxruntime / pillow / pymupdf | 建 venv + 写配置 =python= 键                 |
| =bin/eimg-ocr-setup --tessdata=          | 下载 chi_sim / eng 语言数据到 tessdata 目录                | 写语言数据文件                               |

=--yes= 跳过交互确认（非交互环境必须给，否则按「已取消」退出 1）； =--python PATH= 与
=--tessdata-dir DIR= 覆盖默认解释器与语言数据目录。

*=--tessdata= 装完即用，无需再配路径* ：语言数据落在 =~/.local/share/eimg/tessdata/=
（遵循 =XDG_DATA_HOME= ），而 =bin/eimg-ocr= 在 **没有** 显式 =--tessdata-dir= 时会自动使用
该目录（前提是里面已有 =*.traineddata= ），探测的 =reason= 里会注明
=默认使用 eimg 安装目录: …= 。只有把语言数据放在别处才需要显式指向。

*=--tessdata= 按内容校验* ：脚本内置 =chi_sim= / =eng= 的 SHA256，下载后比对，不一致即失败
（退出码 1）并删除半成品；已存在且校验通过时跳过下载（不联网）。上游 =tessdata_fast= 改版后
需同步更新脚本里的 =TESSDATA_SHA256= ，否则下载会被判为「内容校验不通过」。

需要更新哈希时先算新值： =sha256sum chi_sim.traineddata= （或 =python3 -c 'import hashlib,sys;print(hashlib.sha256(open(sys.argv[1],"rb").read()).hexdigest())' 文件= ）。只用你自己下载并确认过的文件算，不要用测试夹具的哈希。

*CA 证书报错的排错* ： =--tessdata= 下载时报
=SSL: CERTIFICATE_VERIFY_FAILED ... unable to get local issuer certificate= ，说明
**解释器** 的 CA 配置有问题（常见于 conda / 自编译 Python：编译期 cafile 路径不存在，且
不看 =SSL_CERT_FILE= ），系统信任库本身通常是好的（ =curl= 能通）。脚本已自动按顺序尝试
=/etc/ssl/cert.pem= 、 =/etc/ssl/certs/ca-certificates.crt= 、
=/etc/pki/tls/certs/ca-bundle.crt= 与已安装的 =certifi= ，全部不可用才回退解释器默认。
若仍失败，显式兜底一次： =SSL_CERT_FILE=/etc/ssl/cert.pem bin/eimg-ocr-setup --tessdata= ——
错误文案里会带「本次用的 CA」与可复制的这条命令。

这一点只在走本脚本时被绕开：同一台机器上不经 =bin/eimg-ocr-setup= 的其它 Python 下载仍会撞上
同一问题——根治要给解释器配好 =certifi= / =SSL_CERT_FILE= ，或改用系统 =python3= 。

** 后端矩阵

| 后端        | 依赖                                                                               | 中文精度                                                         | 备注                                                                                                        |
|-------------+------------------------------------------------------------------------------------+------------------------------------------------------------------+-------------------------------------------------------------------------------------------------------------|
| =rapidocr=  | Python + onnxruntime + numpy + pillow                                              | 高（截图场景首选，故 =auto= 排第一）                             | 模型固定中英文， =--lang= 被忽略且不报错                                                                    |
| =ollama=    | 本地 ollama 服务 + 视觉模型（如 qwen2.5vl / minicpm-v / gemma3 / llama3.2-vision） | 视模型而定（复杂版式 / 表格强于几何引擎，但无 box/conf、速度慢） | 模型必须显式配置，未配置即判不可用；只支持 png / jpg / jpeg                                                 |
| =tesseract= | =tesseract= 可执行文件 + chi_sim / eng 语言数据                                    | 较低                                                             | 缺语言数据时探测即判不可用；装了 =--tessdata= 后 CLI 默认使用 =~/.local/share/eimg/tessdata= ，无需额外配置 |
| =auto=      | —                                                                                 | —                                                               | 探测顺序：rapidocr → ollama → tesseract，取第一个可用者                                                   |

rapidocr 的解释器解析顺序（ =--python= 一旦给出就只用它，不再往下探测）：
=--python= → =EIMG_OCR_PYTHON= 环境变量 → =config.json= 的 =python= 键 → =PATH= 上的
=python3= → 已知 venv（ =pdf-toc-ocr= 的 =~/.venv/bin/python= ）。路径无效即视为 rapidocr
不可用，不会抛 traceback。

ollama 后端的模型与服务地址解析顺序：模型 =--ollama-model= → =config.json= 的 =ollama_model=
（ *无内置默认，未配置即不可用* ， =auto= 直接跳过它）；地址 =--ollama-url= → =config.json=
的 =ollama_url= → 内置 =http://127.0.0.1:11434= 。可用性判据是「HTTP 可达 + 模型已安装且
声明支持视觉」（探测 =POST /api/show= 的 =capabilities= ）， **不是** =which ollama= ——典型
形态是 ollama 装在 Windows 原生侧、WSL 里根本没有该命令，但经 mirrored 网络仍能访问
=127.0.0.1:11434= 。

=--list-backends= 与 =--check= 会发一次本地 HTTP 请求（探测 ollama）：ollama 未运行时是毫秒级的
连接拒绝，但端口被防火墙 DROP 或对端不响应时最多等 3 秒。不要把它们放进 shell 补全、
=init= 或任何启动路径。

** ollama 后端的安全边界

- =--ollama-url= 只接受 =http= / =https= ，且拒绝 =user:pass@= 形式（凭据会进日志与 buffer，
  改用代理侧认证）。
- 重定向一律拒绝：服务端 302/307 不会被跟随（防止把图片或请求引向别的主机）。
- 响应体上限 16 MB、单张图片上限 32 MB；超限按识别失败 / 输入不可读处理。
- 回环端口不等于可信：ollama 未运行时同机其它进程可抢占 11434 冒充服务，被 OCR 的图片
  会发给它。ollama 自身无认证，别把 =--ollama-url= 指向不受信任的主机。
- 识别结果文本来自网络对端； =eimg-ocr-report-style= 为 =org= 时结果 buffer 里可能出现
  =#+= 之类行，导出前自己确认（本包只做纯文本插入，不 =eval= 任何内容）。

配置与数据目录： =~/.local/share/eimg/= （遵循 =XDG_DATA_HOME= ），内含 =config.json= 、
=venv/= 、 =tessdata/= 。 =--check= 会逐项打印它们的现状。

* 截图与图片插入

截图链路是基础能力（OCR 的 =eimg-ocr-region= 也复用它），由四个模块组成：采集
（ =eimg-capture.el= ）、选择预览（ =eimg-select.el= ）、插入（ =eimg-insert.el= ）、
embark 集成（ =eimg-embark.el= ）。四者都在 =(require 'eimg)= 时加载，顶层零第三方依赖
（consult / posframe / embark 一律在函数体内懒加载）。

** 命令

| 命令                          | 作用                                                        | 返回               |
|-------------------------------+-------------------------------------------------------------+--------------------|
| =eimg-capture=                | 调外部截图工具，存到截图目录并写历史，成功后 *只提示不插入* | 截图文件的绝对路径 |
| =eimg-capture-open-directory= | 用 Dired 打开 =eimg-capture-directory=                      | —                 |
| =eimg-insert-path=            | 插入图片链接； =C-u= 改为插入内联图片                       | —                 |
| =eimg-insert-display=         | 把图片插入为内联显示（ =:max-width= / =:max-height= 夹住）  | —                 |

采集与插入刻意分离：采集只负责「拿到一张图」，插入才决定「怎么放进当前文档」。
=eimg-capture= 的成功判据是 *双条件* （退出码 0 且目标文件存在）；失败时删除半成品并
=user-error= （带命令名与退出码），不写历史、不静默。

=eimg-insert-path= / =eimg-insert-display= 的选区语义一致：活动选区文本能解析成图片路径
就替换选区；解析失败则删选区并弹选择界面。仅当进入时处于 evil visual state 才在结束时回
normal（normal / insert 下不切 state，避免打断输入）。

** 配置项（8 个，分属三个模块）

| 配置项                          | 默认值              | 所属    | 用途                                                    |
|---------------------------------+---------------------+---------+---------------------------------------------------------|
| =eimg-capture-directory=        | =nil=               | capture | 截图落盘目录； *未配置时 =user-error=* ，绝不猜目录     |
| =eimg-capture-command=          | ="flameshot.exe"=   | capture | 截图程序名（在 =exec-path= 中查找）                     |
| =eimg-capture-command-args=     | ='("gui" "--path")= | capture | 传给截图程序的参数，目标文件路径追加在末尾              |
| =eimg-capture-history-size=     | =200=               | capture | 历史最大条目数，超出丢弃最旧                            |
| =eimg-capture-history-file=     | =nil=               | capture | 历史文件绝对路径； *未配置时写入 =user-error=*          |
| =eimg-select-item-roots=        | =nil=               | select  | 「全部图片」候选的递归扫描根目录（每次打开都全量扫描）  |
| =eimg-select-preview-max-width= | =700=               | select  | 预览与内联插入的像素宽上限                              |
| =eimg-insert-plain-path-modes=  | ='(eca-chat-mode)=  | insert  | 只插裸缩写路径（不包 org / markdown 链接）的 major-mode |

注意 =eimg-capture-directory= 与 =eimg-ocr-images-dir= 是 *两个不同的变量* ：前者是截图
落盘目录（ =eimg-capture= 写入位置），后者是 OCR 的图片目录（ =eimg-ocr-file= 的默认目录、
=eimg-ocr-history= 的扫描目录）。典型配置让后者指向前者，但两者互不推断——只有一个被配置时
另一个不会自动跟随。

** 插入格式（四模式）

| 场景                                                         | 插入形态                  |
|--------------------------------------------------------------+---------------------------|
| =eimg-insert-plain-path-modes= 家族（默认 =eca-chat-mode= ） | =~/pics/a.png= （裸路径） |
| =org-mode=                                                   | =[[file:~/pics/a.png]]=   |
| =markdown-mode=                                              | =![](file:~/pics/a.png)=  |
| 其他 major-mode                                              | =~/pics/a.png= （裸路径） |

判序是 *硬约束* ： =eimg-insert-plain-path-modes= 分支必须排在 =markdown-mode= 之前——
=eca-chat-mode= 经 =gfm-mode= 两跳派生自 =markdown-mode= ，排在后面就永远命不中。路径一律
=abbreviate-file-name= （图片与文档物理分离，且 =~/Org= 是符号链接，相对路径的基准随打开
方式变化必有一端失效）。

=eimg-insert-display= 的退化顺序：命中裸路径模式 → 只插路径文本并 =message= 提示；无图形能力
（ =display-graphic-p= 为 nil）或图片类型不受支持 → 插链接并提示；其余情况插入带
=:max-width= （ =eimg-select-preview-max-width= ）与 =:max-height= （窗口 body 高度的一半）
的内联图片对象。

** 历史文件

=eimg-capture-history= 是 plist 列表，元素 =(:path <绝对路径> :time <时间字符串>)= ，最新在
头部；每次 push 后 *立即落盘* （daemon 崩溃不丢记录）。push 的顺序固定：同一路径去重 →
头插 → 按 =eimg-capture-history-size= 从尾部截断 → 写文件。

落盘编码固定 =utf-8-unix= ，读入只用 =read= 不 =eval= （历史是数据，不得执行其中代码）。
读取时逐条做结构校验（合法 = 列表 plist 且 = :path= 是字符串）：手工编辑、旧版本残留留下的
=("a" "b")= 之类形态会被整份忽略并 =message= 提示，而不是让 =plist-get= 抛
=wrong-type-argument= 。已在磁盘上消失的路径在取候选时过滤（历史保留、候选不含）。

** embark 集成

选择界面的候选 category 是 =eimg/image= ，注册在 =embark-keymap-alist= 上。在候选上按
=C-.= 得到动作菜单：

| 键          | 动作                                         |
|-------------+----------------------------------------------|
| =i=         | 插入图片链接（ =eimg-embark-insert-link= ）  |
| =b=         | 插入内联图片（ =eimg-embark-insert-image= ） |
| =RET= / =f= | 打开文件                                     |
| =o=         | 在另一窗口打开                               |
| =x=         | 外部程序打开                                 |
| =d=         | 删除文件                                     |
| =w=         | 复制路径                                     |

=i= / =b= 是对 =embark-general-map= 同名键的显式覆盖（ =i= 原本是 =embark-insert= ），
其余键继承自 =embark-general-map= 。整个注册在 =with-eval-after-load 'embark= 内，未装
embark 时本模块仍能加载。multitarget（多选）时每个目标各插一次。

* CLI 用法

** 参数表

| 参数                | 取值                                         | 默认                     | 说明                                                                    |
|---------------------+----------------------------------------------+--------------------------+-------------------------------------------------------------------------|
| =--backend=         | =rapidocr= / =ollama= / =tesseract= / =auto= | =auto=                   | 后端选择； =auto= 按 rapidocr → ollama → tesseract 取第一个可用者       |
| =--lang=            | tesseract 语法，如 =chi_sim+eng=             | =chi_sim+eng=            | 识别语言；rapidocr 忽略此参数（传了也不报错）                           |
| =--format=          | =text= / =json= / =lines=                    | =text=                   | =text= 按页输出、页间 =\\f= 分隔； =lines= 每行一条文本； =json= 结构化 |
| =--pdf-pages=       | 如 =1-5= 或 =3=                              | 全部页                   | PDF 只识别指定页；页码越界退出码 3。对图片无意义，会被忽略              |
| =--dpi=             | 整数，如 =300=                               | =200=                    | PDF 栅格化精度                                                          |
| =--page-images-dir= | =DIR=                                        | 不落页图                 | PDF 页图落盘目录（ = <主干>-p<页码>.png= ）；json 每页多 =image= 键     |
| =--python=          | 路径                                         | 自动探测                 | rapidocr 解释器；给了就只用它，无效即判 rapidocr 不可用                 |
| =--tessdata-dir=    | 路径                                         | 自动                     | 语言数据目录；不给时先系统默认、再 =~/.local/share/eimg/tessdata=       |
| =--ollama-model=    | 模型名，如 =qwen2.5vl:7b=                    | 未配置                   | ollama 视觉模型； *无内置默认* ，未配置即判 ollama 不可用               |
| =--ollama-url=      | URL，如 =http://10.0.0.5:11434=              | =http://127.0.0.1:11434= | ollama 服务地址； =config.json= 的 =ollama_url= 优先于该默认            |
| =--list-backends=   | （无值）                                     | —                       | 列出后端可用性后退出；查询动作，无论有无可用后端都返回 0                |

位置参数 =FILE ...= 可给多个，支持扩展名： =png= / =jpg= / =jpeg= / =webp= / =bmp= /
=tif= / =tiff= / =gif= / =pdf= 。

=--page-images-dir= 决定「页图落不落盘、落在哪」：PDF 的每页栅格 PNG 落到 DIR，命名
=<源文件名主干>-p<真实页码>.png= （ =--pdf-pages 3= 时落的是 =x-p3.png= ，不是
=x-p1.png= ），json 的每页因此多一个 ="image"= （绝对路径）；图片输入没有栅格化产物，
="image"= 直接指向输入图本身（不复制文件）。DIR 不存在会自动创建（含多级），建不出来 /
不可写 / 已是普通文件一律按 *参数错误* 退出 5，而不是退出 3——目录路径是命令行上敲进来的
参数，与「输入文件读不出来」是两类问题。 *不传该参数时 json / text / lines 三种输出与旧版
逐字节一致* （块序列、字段顺序、页间分隔符都没变），旧调用方与快照测试不受影响。校验发生
在 =main()= 的 =try= 内且优先于查询动作： =--list-backends --page-images-dir /x= 也会顺手把
=/x= 建出来（已知副作用，只会是一个空目录）。

页图的下游消费者是联动视图，见下一节；elisp 侧识别 PDF 时会自己建临时目录，用户只在
「想留住页图」时才需要手敲这个参数。

** 示例

#+begin_src shell
# 1. 先看后端现状（零写入）
bin/eimg-ocr-setup --check

# 2. 列后端可用性（CLI 自检；与上一条的区别是不关心配置文件与安装位置）
bin/eimg-ocr --list-backends

# 3. 识别单张图，默认 auto + text（页间 \f 分隔）
bin/eimg-ocr screenshot.png

# 4. PDF 只识别第 2–5 页，300 dpi，结构化 JSON 输出
bin/eimg-ocr --pdf-pages 2-5 --dpi 300 --format json report.pdf

# 5. 指定后端与显式解释器，并一次识别多张图
bin/eimg-ocr --backend rapidocr \
  --python ~/.local/share/eimg/venv/bin/python a.png b.png

# 6. 用本地 ollama 的视觉模型识别（模型必须显式指定）
bin/eimg-ocr --backend ollama --ollama-model qwen2.5vl:7b shot.png

# 7. PDF 每页栅格图落到指定目录，JSON 的每页带上 image 绝对路径（联动视图用）
bin/eimg-ocr --format json --page-images-dir /tmp/eimg-pages report.pdf
#+end_src

=--format json= 的形态：顶层 ={"backend": "...", "pages": [...]}= ，每页
={"page": N, "source": "<输入文件 basename>", "blocks": [{"text", "conf", "box"} ...]}= 。
=page= 是 *真实页码* （ =--pdf-pages 2= 时第一个元素的 =page= 就是 2），elisp 侧依赖它回填
文件名。给了 =--page-images-dir= 时每页还多一个 ="image"= （页图绝对路径）；不给则该键
不出现（不是 ="image": null= ，否则不传参数的调用方会拿到字段集合变了的 JSON）。三种格式
都由同一份块序列派生，块按阅读顺序（先行后列）排列。

** 退出码契约

| 码  | 含义                                                                                           | stderr 关键子串         |
|-----+------------------------------------------------------------------------------------------------+-------------------------|
| =0= | 成功（含 =--list-backends= 的查询结果）                                                        | —                      |
| =2= | 无可用 OCR 后端（ollama 需显式配置模型： =--ollama-model= / =config.json= 的 =ollama_model= ） | =未找到可用的 OCR 后端= |
| =3= | 输入不可读 / 不存在 / 不支持格式 / 页码越界 / PDF 无法栅格化（缺 =pdftoppm= 、文件损坏或加密） | =无法读取输入=          |
| =4= | 识别失败（含后端超时）                                                                         | =识别失败=              |
| =5= | 参数错误                                                                                       | =参数错误=              |

所有 stderr 行统一带 =eimg-ocr: = 前缀。elisp 侧只按 *退出码* 分支，不解析 stderr 文案；
文案由 =eimg-core-exit-message= / =eimg-core-exit-hint= 拼装（这是退出码语义的单一事实来源）。
=bin/eimg-ocr-setup= 的退出码是另一套： =0= 成功 / =1= 用户取消或安装失败 /
=2= 前置条件不满足 / =5= 参数错误。

** 联动视图（位置对齐）

结果 buffer 里按 =v= （或菜单「系统」组的 =v= ）打开 =*eimg-ocr-view*= ，它把一次识别的
*结构化* 结果摆成能对照的两半：

- 上半部分是 *原图带框* ：底图是原图（PDF 输入是 CLI 栅格化出来的页图），每块文字在自己
  =box= 的位置上画一个框，当前块用异色描边 + 半透明填充标出。
- 下半部分是 *文本列表* ：每行一块；多行块在列表里压成一行（完整原文仍保留在块数据里，
  复制拿到的是原文，不是压平后的那行）。

两侧 *双向联动* ：文本行的光标移动 → 图上对应的框高亮；鼠标点图上的框 → 光标跳到对应文本行。

| 键位  | 命令                           | 作用                           |
|-------+--------------------------------+--------------------------------|
| =n=   | =eimg-ocr-view-next-block=     | 下一块（跨页自动换页）         |
| =p=   | =eimg-ocr-view-previous-block= | 上一块（跨页自动换页）         |
| =N=   | =eimg-ocr-view-next-page=      | 下一页                         |
| =P=   | =eimg-ocr-view-previous-page=  | 上一页                         |
| =RET= | =eimg-ocr-view-copy-block=     | 复制当前块文本到 kill-ring     |
| =o=   | =eimg-ocr-view-open-image=     | 打开当前页的位图文件           |
| =g=   | =eimg-ocr-view-revert=         | 重新从结果 buffer 取数据并重渲 |
| =q=   | =quit-window=                  | 关闭视图                       |

=RET= 是 *复制* 而非「跳到原图位置」：原图在 Emacs 里是一整张图片（不可分割的显示对象），
没有「图片内位置」这种坐标可供定位，同一位置真正有用的动作是拿走那段文字。

降级路径一律 *不报错* （文本列表照常可用，图区改写成一行能读懂的原因）：

- 结果 buffer 里没有结构化数据（ =v= 出现之前的旧版结果）→ =user-error= ，提示重新识别。
- 当前页的块全都没有 =box= （ollama 后端）→ 只显示文本列表，并提示「后端不提供 box」。
- 找不到页图 → 只显示文本并说明缺什么（PDF 输入 / 重新识别）。
- 原图字节数超过 =eimg-ocr-view-max-embed-bytes= （默认 8 MB）→ *降级为纯文本列表* ，并提示
  「降低 =--dpi= 重新识别，或裁剪图片后再识别」。为什么是降级而不是降采样：Emacs 内置无法把
  图片缩放后导出字节（ =create-image= 的 =:width= 只影响显示），真降采样需要额外的图像后端，
  与「顶层零第三方依赖」冲突。
- 页图读不出尺寸或读不出内容 → 只显示文本，提示里带路径与原因。

*前提是 SVG* ：位图叠加走 SVG 合成（底图以 base64 =<image>= 内嵌，框是 =<rect>= ），要求
Emacs 编译时带 librsvg，即 =(image-type-available-p 'svg)= 为 t。缺 SVG 支持时建不出图、图区
走降级路径（代码里有显式判定，会直接说「当前 Emacs 没有 SVG 支持」，而不是含糊的「本页暂无
可显示的页图」），文本列表与光标联动仍可用。中文译文（后续计划）另外依赖系统装 CJK 字体。

*页图的生命周期* ：输入含 PDF 且调用方没显式给 =:page-images-dir= 时，识别过程自动建一个
临时目录让 CLI 把每页栅格图落进去，成功后交给结果 buffer；结果 buffer 被 kill、或 =g= 重新
识别（覆盖旧结果）时删掉旧目录，失败 / 取消 / 解析失败则当场删。单图输入不落页图（ ="image"=
直接指向输入图），视图回退用元信息里的 =:source= 原图——要求它是绝对路径，只有文件名时不猜
目录、直接降级。

性能参考：24 块一页时，光标移动触发的重绘约 2ms（只重插图区，不重建文本列表）。底图 base64
走 *前缀缓存* （失效键是「路径 / mtime / size / 原图宽高 / 显示宽高」），重绘只重拼 =<rect>=
那几十行：5.6 MB SVG 的一页上实测从 62.6 ms/次降到 2.2 ms/次（GC 次数 7 → 3），缓存命中与
未命中的输出字符串逐字相同。

* 已知边界

- *阅读顺序只还原单栏横排* ：多栏（双栏论文 / 并排代码）会左右交错，竖排会一字一行。
  实现刻意只做「按 y 中心聚行 + 行内按 x0」，宁可排错也不猜版面。
- *无 =pdfinfo= 时部分页码越界会静默截断* ： =--pdf-pages 2-9= 打在 3 页文档上，
  =pdftoppm= 返回 0 且只输出 2、3 两页——没有总页数就没有判据。有 =pdfinfo= 时走
  前置校验，越界报退出码 3。
- *=--pdf-pages= 对多 PDF 混排重复生效* ：页码范围对每个输入文件都套用，第二个文件页数
  不足就整批以退出码 3 失败，前面已识别的结果被丢弃。批量场景先别带 =--pdf-pages= 。
- *=eimg-ocr-region= 需要图形环境* ：无 =display-graphic-p= 时直接 =user-error= ，不去
  硬跑截图函数。
- *交互命令在 daemon / 批处理下会阻塞* ：OCR 本身是异步的，但 =eimg-ocr-region= 用
  =call-interactively= 同步等外部截图进程， =eimg-ocr-file= / =eimg-ocr-history= 用
  =read-file-name= / =completing-read= ， =eimg-ocr-write-file= 覆盖前 =y-or-n-p=——这些
  提示在没有 attached frame 的 daemon 或 =noninteractive= 里无法完成。
- *预览需要 GUI + posframe* ：选择界面的预览走 child frame（posframe）。缺图形能力、缺
  posframe 或图片类型不受支持时一律 *降级* —— 只 =message= 或静默关闭预览，不向上抛错，
  「挑图」本身照常可用。
- *=eimg-capture= 同步等外部程序* ：内部用 =call-process= ，截图工具不返回就一直占住主线程
  （与 OCR 的异步进程层不同）。截图工具的弹窗行为、退出码语义由它自己决定，eimg 只判
  「退出码 0 且文件存在」这两条。
- *=eimg-capture-directory= 未配置时 =user-error=* ：不猜目录、不静默写到 =default-directory= 。
  =eimg-capture-history-file= 同理（丢记录必须是可见的失败）。
- *ollama（VLM）后端不提供 =box=* ：联动视图对它的识别结果只有文本列表、图上无框（不报错，
  图区写明原因）。要框就得用 rapidocr 或 tesseract。
- *单图输入的「页图」就是原图本身* ：不复制、不落盘，视图回退到元信息里的 =:source= ；它若
  只是文件名（无绝对路径）就不去猜目录，直接降级为无图。
- *=--page-images-dir= 的目录创建优先于查询动作* ： =--list-backends --page-images-dir /x=
  会顺手建出 =/x= 。副作用仅此（空目录）；不想留空目录就别把它和查询参数混用。

=TEST_TMPDIR= 是 =make test= 的关键细节：目标里把 =TMPDIR= 显式钉到 =$(CURDIR)/.tmp-test= ，
不继承调用者环境。因为 ERT 用例里的 =make-temp-file= 走 Emacs 的 =temporary-file-directory= ，
而它直接取自 =TMPDIR=——一旦 =TMPDIR= 指向别的仓库，测试产物（ =out.org= 、stub 脚本）
就会写进别人的版本库，且测试自己看不见。钉进仓库后产物与仓库同生命周期，跑完即删。
